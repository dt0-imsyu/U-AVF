# U-AVF contributor instructions

## Documentation

- Write concise technical English. Use the exact file, class, command and option names.
- Check claims against source, build scripts and test evidence. Identify experimental paths and describe their observed limits.
- Explain component ownership, interfaces, data flow and operational choices. Add a table or diagram when it makes those relationships easier to follow.
- Update the existing guide for a topic. The root README introduces the project, and `android-app/README.md` describes the Android source and build.
- Check links, obsolete descriptions and repeated content. Preserve details that affect build reproducibility, compatibility or data safety.
- Use the project-local `technical-writing` and `de-slopify` skills to edit documentation and `docs-check` for read-only verification, when available. These skills are optional developer tools.
