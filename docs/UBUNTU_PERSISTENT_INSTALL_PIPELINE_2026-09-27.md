# U-AVF persistent Ubuntu install pipeline — 2026-09-27

## Implemented in source

- The Linux workspace now distinguishes a persistent disk with a confirmed U-AVF runtime from a disk whose setup still needs verification.
- Creating a new persistent disk resets only the corresponding app-state flags. It does not recreate or erase an existing disk.
- The first-install automation waits for the Live install profile's 4051 revision-1 readiness response before opening GNOME Run and invoking Canonical's documented bootstrap entry point with `--try-or-install` and the snap desktop-file hint. It skips this automation for the installed-runtime revision, then sends GNOME maximize and F11 fullscreen requests after a startup delay.
- The install profile retains the proven P40/P7-derived single-disk layout: platform EFI, official ISO partition, and the dedicated `U-AVF Ubuntu Root` target.
- Before first install launch, the app shows a safety confirmation. It explicitly forbids Ubuntu's whole-disk erase option and directs the user to format only the dedicated root partition as ext4 mounted at `/`.
- The Live initrd bootstrap accepts writes only when `/target` is ext4 and its GPT partition label is exactly `U-AVF Ubuntu Root`; it also checks Ubuntu 24.04 and required GNOME files before staging anything.
